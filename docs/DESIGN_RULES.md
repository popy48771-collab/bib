# UIデザイン方針（依頼原文）

このファイルは、2026-08-17 に受け取ったUI改修の指示を**原文のまま**保存したものである。
実装で日々参照する要約版は [../DESIGN_SYSTEM.md](../DESIGN_SYSTEM.md)。
判断が食い違ったときは、こちらの原文を優先する。

## 目的

現在のUIには、グラデーション、多用された角丸カード、過剰な余白、装飾アイコンなど、AIが自動生成したウェブアプリにありがちな印象があります。

これを、図書館の検索システムや行政のオンライン手続サービスに近い、質実剛健で信頼できる画面へ変更してください。

目指す印象は以下です。

* 公共的
* 誠実
* 正確
* 静か
* 実務的
* スマートフォンで迷わず使える
* 流行に左右されにくい
* 図書館・書誌データベースとの親和性がある

「おしゃれ」「親しみやすい」「未来的」「AIらしい」は目標にしません。

## 参照するデザイン

第一の参照先は、デジタル庁デザインシステムとしてください。

https://design.digital.go.jp/dads/

必要に応じて、以下のプレーンHTML版コンポーネントも参照してください。

https://github.com/digital-go-jp/design-system-example-components-html

ただし、デジタル庁のロゴ、政府機関の紋章、政府公式サービスと誤認させる表現は使用しないでください。ブランドをコピーするのではなく、情報設計、アクセシビリティ、タイポグラフィ、フォーム、ボタンなどの設計原則を借りてください。

## 不変条件

* バーコード読取機能を壊さない
* NDLサーチAPIとの通信処理を壊さない
* 既存の登録・削除・一覧表示機能を維持する
* GitHub Pagesで公開できる静的構成を維持する
* デプロイ時のベースパスや相対パスを壊さない
* 現在のフレームワークを維持する
* デザイン目的だけの新しいUIライブラリを追加しない
* APIキーやバックエンドを新たに要求しない

## デザイントークン

CSS変数として一か所にまとめ、画面内で任意の色・角丸・影を追加しないでください。

* ページ背景：#f7f7f7
* コンテンツ背景：#ffffff
* 主文字：#1a1a1a
* 補助文字：#4d4d4d
* 薄い補助文字：#666666
* 境界線：#949494
* 薄い境界線：#d9d9d9
* プライマリー：#0017c1
* プライマリーHover：#00118f
* エラー：#b10e1e
* 成功：#006e54
* フォーカス：#ffd43b

色は意味を持つ箇所だけに使用し、基本画面は白・薄いグレー・濃い文字で構成してください。プライマリーカラーは主要ボタン、リンク、現在地表示に限定してください。

## タイポグラフィ

外部Webフォントは必須にせず、次のシステムフォントを使用してください。

system-ui, -apple-system, BlinkMacSystemFont, "Hiragino Sans", "Yu Gothic UI", "Yu Gothic", "Noto Sans JP", sans-serif

* 本文：16px、行高1.6
* ページ見出し：24px、700、行高1.4
* セクション見出し：20px、700、行高1.4
* 小見出し：17px、700
* 補助情報：14px、行高1.5
* 14px未満の文字は禁止
* 通常本文に300や極端に細いウェイトを使用しない
* 見出しを不必要に巨大化しない
* 英字の字間を広く取らない

## 余白と形状

余白は 4 / 8 / 12 / 16 / 24 / 32px の段階だけを使用してください。

* スマートフォン左右余白：16px
* コンテンツ最大幅：720px
* 通常の角丸：4px
* 大きくても6pxまで
* タグ以外で完全なカプセル形状を使用しない
* 通常のカードや一覧行に影を使用しない
* 区切りは1pxの境界線と余白で表現する
* モーダルなど、実際に前面へ浮く要素にだけ弱い影を使用する

## 画面構成

### ヘッダー

* 白背景
* 上端に4pxのプライマリーカラー
* サービス名を18px程度の太字で表示
* 大きなロゴ、キャッチコピー、イラストは置かない
* ナビゲーション項目は必要最小限にする

### バーコード読取画面

情報の順番を以下にしてください。

1. 「本のバーコードを読み取る」という見出し
2. 「裏表紙の、978または979から始まるバーコードをカメラに収めてください」という短い説明
3. カメラ表示領域
4. 現在の状態
5. 主操作ボタン
6. 登録済み件数と一覧へのリンク

カメラ領域は四角形に近い形とし、派手な発光、グラデーション、常時動くスキャン線は使用しないでください。読取位置を示す必要がある場合は、単純な枠線または四隅のマーカーだけにしてください。

主ボタンは高さ48px以上、角丸4px、単色の青とします。ボタン文言は「カメラを開始」「再読み取り」「一覧に追加」のように、具体的な動詞を使用してください。

### 書誌一覧

本ごとに独立した浮遊カードを並べないでください。一つの白い一覧領域の中を境界線で区切る、図書館OPACに近いリスト表示にしてください。

各行は以下の順序とします。

* 書名
* 著者
* 出版社・出版年
* ISBN
* 必要に応じてシリーズ・巻号
* 削除などの副次操作

書名を最も強くし、ISBNや登録日時は補助情報として扱ってください。書影がある場合も小さく表示し、書影が一覧の主役にならないようにしてください。

### フッター

以下のような簡潔な情報を表示してください。

* 「書誌情報：国立国会図書館サーチ」
* 必要な利用条件・プライバシー情報へのリンク
* 国立国会図書館の公式サービスではないことが必要なら明示する

## 文体

画面内の文章は、公的サービスの案内文に近い簡潔な日本語にしてください。

使用しない表現：

* 「さあ、はじめましょう！」
* 「スキャンしてみよう」
* 「おっと！」
* 「素晴らしい！」
* 絵文字
* 感嘆符
* 不要な英語見出し
* 広告的なキャッチコピー

推奨表現：

* 「本のバーコードを読み取ります」
* 「書誌情報を取得しています」
* 「書誌情報を一覧に追加しました」
* 「このISBNは登録済みです」
* 「書誌情報が見つかりませんでした。ISBNを確認して、もう一度読み取ってください」
* 「カメラへのアクセスが許可されていません。ブラウザの設定を確認してください」

エラー文は「何が起きたか。次に何をすればよいか。」の順にしてください。

## 必要な画面状態

正常時だけでなく、以下をすべて整えてください。

* 初期状態
* カメラ起動中
* バーコード探索中
* ISBN読取成功
* NDLサーチへの問い合わせ中
* 書誌登録成功
* 同じISBNの重複
* 書誌情報なし
* 通信エラー
* オフライン
* カメラ権限拒否
* 蔵書一覧が空
* 蔵書一覧にデータあり
* 削除確認

色だけで状態を伝えず、必ず文章またはアイコンと文章の組み合わせで示してください。

## 禁止するデザイン

* グラデーション
* glassmorphism
* ネオン色
* 紫を中心にしたAIサービス風配色
* 大きなヒーローセクション
* 装飾目的のイラスト
* キラキラ・魔法・AIを連想させるアイコン
* すべてをカードで囲むレイアウト
* 過剰な角丸
* 常時表示される大きな影
* 多数の色付きバッジ
* 意味のないアニメーション
* ホバー時に要素が大きく浮き上がる表現
* スマートフォンで場所を取る説明文
* アイコンだけで意味を伝えるボタン

## アクセシビリティ

WCAG 2.2 AAを目標としてください。

* 本文と背景のコントラスト比4.5:1以上
* UI部品と背景のコントラスト比3:1以上
* タップ領域44×44px以上
* キーボード操作可能
* 明確なフォーカス表示
* input、buttonに適切なlabelまたはaccessible name
* 読取結果やエラー通知にaria-liveを適切に使用
* prefers-reduced-motionに対応
* 拡大表示時も横スクロールを発生させない
* 色だけで成功・エラー・選択状態を区別しない

## 実装手順

1. 現在の画面、コンポーネント、CSSを確認する
2. AI的な印象を作っている箇所を特定する
3. CSS変数によるデザイントークンを作る
4. 全画面を同じ規則へ統一する
5. ハッピーパス以外の状態も整える
6. モバイル幅390pxと375pxで確認する
7. PC幅でも破綻しないことを確認する
8. 既存のビルド・テストを実行する
9. GitHub Pages用のビルドが成功することを確認する
10. 変更点と確認結果を報告する

今後の改修でもデザインが崩れないよう、主要なデザイントークン、コンポーネント規則、禁止事項を簡潔なDESIGN_SYSTEM.mdとしてリポジトリにも保存してください。
