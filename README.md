# 本棚スキャナ

本のバーコード、または**本棚の背表紙**にカメラをかざすと、書誌情報を調べて蔵書一覧
（CSV / JSON / Markdown / BibTeX / ISBN一覧）を作るツール。
サーバを持たない静的サイトとして GitHub Pages で動きます。

- 決定事項の要約（引き継ぎ用）: **[CLAUDE.md](CLAUDE.md)**
- 設計の背景: **[docs/CONCEPT.md](docs/CONCEPT.md)**
- 画面の規則（UIを触る前に読む）: **[DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)**

## 使い方

1. **「カメラを開始」を押す**
2. **かざす**

これだけです。**設定も、そのあとのボタン操作もありません。**
読み取った端から書誌情報を調べ、下の一覧に並べていきます。
できあがった一覧は CSV などに書き出せます。

> **カメラは HTTPS でのみ動きます。** 公開URL（<https://popy48771-collab.github.io/bib/>）
> か `localhost` から開いてください。素の http では必ず失敗します。

### 読み取り方式

画面下の「読み取り方式を変える」で切り替えます。

| 方式 | 向いている場面 |
|---|---|
| **バーコード** | 確実に登録したいとき。ISBN で完全一致するので、書誌情報はそのまま採れます |
| **本棚の背表紙** | 冊数が多く、本を手に取りたくないとき。棚にかざして流すだけで済みます |

#### バーコード

本の裏表紙のバーコードにかざします。1冊ずつ、次々に読めます。

バーコードは2段になっていますが、読むのは上段（978/979 で始まる ISBN）だけです。
下段（192…）は分類・価格コードで、本のIDではありません。

#### 本棚の背表紙

**スマートフォンを横向きにして、棚の一段が枠いっぱいに収まる距離で構え、少し止めてください。**
1枚から20〜30冊をまとめて読み取り、書誌情報を調べて一覧へ足していきます。
読み取りが終わったら、次の段へ移してください。

- 撮れると**端末が短く振動します**。棚を見たままでも取り込めたことが分かります
- 静止したときに撮った**棚一段の画像を Google Gemini API へ1回送信**し、縦書き・横書きをまとめて読み取ります。ライブ映像を連続送信することはありません
- Gemini が利用できない場合は、端末内の Tesseract に自動で切り替わります。その場合だけ、初回に読み取り用データ（約 7MB）を取得します

**いつ終えてよいかは画面が教えます。** 1枚の読み取りには数秒から十数秒かかるので、
撮った瞬間と読み終わった瞬間はずれます。処理が残っているあいだは残り件数が出て、
終わると「**この棚は読み取り終わりました**」に変わります。処理中でも次の段へ移して構いませんし、
**「読み取りを終える」を押しても残りの処理は最後まで続きます**（そのことも画面に出ます）。
すべて終わると書誌一覧に「読み取りと書誌情報の取得が終わりました」と出ます。
- **バーコードと違い、読み取りは必ず外れます。** 誤った本を確定一覧へ混ぜないため、
  次のいずれかを満たしたものだけを自動で確定させます
  - 複数の書誌データベースが同じ ISBN を返した
  - 書名がほぼ完全に一致し、著者も一致した
  - 書名がほぼ完全に一致し、別のコマからも同じ本に行き着いた
- それ以外は「要確認」として一覧に残ります。一度に十数件出ることがあるので、
  **書名がほぼ一致しているものはまとめて確定**でき、**手を入れる必要があるものだけを表示**
  できます。読めなかった本は**読み取り文字を直す**か、**その行のままバーコードで確定**
  できます（行は増えません）

### 書誌情報の調べ先

**ISBN が判っている場合**（バーコード経路）は、当たるまで順に引き、**当たった時点で打ち切ります。**

1. **openBD** — 日本の書籍に強く、1リクエストで返る
2. **Google Books** — 和書のカバレッジは弱いが洋書に強い
3. **NDLサーチ**（国立国会図書館） — 法定納本ぶん網羅性が最も高い

**書名で引く場合**（背表紙経路）は、日本語なら NDL、欧文なら Google Books を先に当て、
**必ず両方に当てます。** 片方だけで高得点でも「1つのDBに似た書名の本があった」に過ぎず、
自動確定の根拠には足りないためです。

読み取った文字は1文字くらい崩れるので、1つの文字列だけでは引きません。
絞りの強い順に複数のクエリへ展開し、**頭のいくつかと、一番当たりの広い1つ**を試します
（末尾を削った前方一致、全項目キーワードなど）。当たったところで打ち切り、
1冊あたりの問い合わせは6回までです。

どれかが落ちていても他で拾えるようにしてあります。
それでも引けなかったものは「見つからず」として一覧に残るので、あとから再照合できます。

一覧の各行では、書き出し対象からの除外（元に戻せます）と、削除（確認のうえ元に戻せません）ができます。

### 書き出しに入るもの

**既定では「確定したもの」だけを書き出します。** 要確認・差分あり・見つからずのものは入りません。
含めたい場合は書き出し画面のチェックボックスで明示的に選びます。
（JSON だけは再取り込み用なので、状態にかかわらず全件を出します）

NDLサーチは CORS 非対応でブラウザから直接呼べないため、中継（`proxy/ndl-worker.js`）を挟みます。
**中継のURLはアプリに埋め込み済みで、設定は要りません。**

## データの保存先

蔵書データと、確認用に切り出した背表紙の画像は IndexedDB に保存されます。
棚一段の静止画像は文字の読み取りのため Google Gemini API へ送信しますが、当サイトの提供者には
送信されません。API には `store: false` を指定し、アプリ自身は棚全体の画像を保存しません。
保存するのは書誌データと背表紙1冊ぶんのクロップだけです。
「蔵書データをすべて削除」では、書誌データと画像の両方を消します。

### デプロイ

`main` への push で GitHub Actions が自動デプロイします（`.github/workflows/deploy.yml`）。
リポジトリの Settings → Pages で Source を **GitHub Actions** に設定してください。

Gemini を有効にするには、Settings → Secrets and variables → Actions → New repository secret で
`GEMINI_API_KEY` を登録します。Actions が `VITE_GEMINI_API_KEY` としてビルドへ渡します。
未設定ならビルドは通り、アプリは端末内 Tesseract だけで動きます。

> GitHub Pages は静的サイトです。Secret はソースや Git 履歴には残りませんが、ビルド後の
> JavaScript には API キーが含まれるため、利用者から確認できます。Google Cloud 側で
> **Generative Language API だけに制限し、利用量・課金上限を設定**してください。

## 既知の制約

- **Gemini API キーを完全には秘匿できない** — GitHub Pages にはサーバ側の秘密領域がありません。キーを本当に隠すには、Cloudflare Workers などの薄い中継が必要です。現構成は利用者本人向けの小規模運用を前提に、API 制限と利用量上限で守ります。
- **Gemini の応答には料金・利用上限・通信状態の影響がある** — 認証失敗、429、タイムアウト、応答形式の不正が起きた読み取りセッションでは、以降を端末内 Tesseract へ自動で切り替えます。
- **NDL のレスポンス解析は実地未検証** — 開発環境から NDL へ到達できなかったため、公開仕様に基づく実装です。名前空間接頭辞の揺れに耐えるよう防御的に書いてありますが、初回接続時に生のレスポンスを確認してください。
- **openBD は収録範囲が縮小している** — 2023年に JPRO からのデータ供給が停止しています。外れたぶんは Google Books と NDL で拾います。
- **iOS Safari は互換モードで動きます** — 内蔵の `BarcodeDetector` が無いため zxing-wasm に退避します（初回スキャン時に約1MB を読み込みます）。
- **言語モデルの配信は実機未確認** — `public/ocr/lang/*.traineddata.gz` は gzip したまま置き、Tesseract 側に展開させています。配信側が `Content-Encoding: gzip` を付けると二重展開になって OCR の初期化に失敗します（GitHub Pages は `.gz` に付けない想定ですが、この開発環境から公開URLへ到達できず未確認）。もし「文字の読み取り機能を読み込めませんでした」が出るときは、まずここを疑ってください。展開済みの `.traineddata` を置き、`src/lib/spine/tesseract.ts` の `gzip: true` を `false` にすれば回避できます。
- **実際の本棚では未実測** — 数字は実寸で合成した本棚での測定です（30冊の棚に、ぼけ・照明ムラ・ノイズを加えて24冊）。正面・平坦・高コントラストという最良条件なので、実物の棚では落ちます。閾値（`src/types.ts` の `SPINE_*`、`src/lib/spine/capture.ts` の品質判定）は実機で調整する前提の初期値です。
- **背表紙が傾いていると落ちます** — 合成した棚に傾きを与えると、10冊中10冊が8冊に落ちました。棚差しの本が斜めになっている場合は、まっすぐに直してから撮るか、バーコードで確定してください。
- **和書に混ざった洋書は拾えないことがあります** — 縦書きとして読んで棚が1本も取れなかったときだけ、90度回して読み直します。和書が読めている棚では、この読み直しが走りません。欧文専用の言語モデル（`eng`）は入れていません（`public/ocr/README.md`）。
